# 실환경 진단과 증거 경계

로컬과 분리된 개발계·스테이징·운영 환경을 진단할 때 적용한다.

1. 분석 전에 대상 환경의 실행 버전(image/tag/commit)·설정·schema를 확인한다. 직접 확인할 수 없으면 간접 신호로 추적하고 결론에 "배포본 미확인"을 명시한다. 로컬 코드에 없는 DB 컬럼·테이블·API·화면은 배포본 차이의 신호다.
2. 코드·설정·데이터·요청 context가 대상 환경과 일치할 때만 "재현"이라 부른다. 다른 조합의 실행은 "가설 실험"이며, 대상 환경이 정상이라는 증거로 쓰지 않는다.
3. 실험 결과가 실제 증상과 다르면 버전·설정·데이터·context 불일치부터 조사한다.
4. UI 증상, 실제 request/response(URL·status·body·앱 error code), 서버 로그 순으로 원시 증거 확보를 시도한다. 확보하지 못한 층은 명시한다. 계정·환경 차이는 플래그·멤버십·테넌트·세션·캐시까지 raw 수준에서 비교하고, 가설에는 가장 싼 반증 실험을 함께 수행한다.
5. "원인 확정"은 관찰된 차이를 설명하고 조치 후 원래 실패했던 동일 화면/API의 성공이 확인된 경우다. 그 전에는 직접 확인한 사실·코드 추론·미확인 가설을 구분하며, 런타임 증거 없이 가설을 "가장 유력"으로 승격하지 않는다.
