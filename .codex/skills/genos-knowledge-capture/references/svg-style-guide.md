# GenOS 설명용 SVG 가이드

SVG를 선택했을 때 읽는다. 실행 위치·포함 관계·책임 범위·망 경계처럼 공간 배치가 이해를 돕는 그림에 사용한다. API 요청 순서는 Mermaid sequenceDiagram, 짧은 항목 비교는 표로 충분할 수 있다. 그림 수를 채우거나 기존 Mermaid를 일괄 교체하지 않는다.

## 근거와 그림의 의미

- 그림 하나마다 독자가 답을 얻을 질문을 정한다. 예: “플랫폼 API와 서빙 워크로드는 어디서 실행되고 registry는 어느 경계 밖에 있는가?”
- 상자가 클러스터·Namespace·Pod·프로세스·망 구간 중 무엇인지 라벨로 구분한다. Namespace 경계를 네트워크 차단이나 별도 커널의 증거처럼 그리지 않는다.
- 화살표에는 요청·응답·이미지 pull·설정 전달 등 실제 의미를 적는다. CI 빌드·배포 제어 경로와 사용자 요청 경로를 구분하고, 논리 단계의 나열을 직접 통신으로 표현하지 않는다.
- 로컬 소스·chart가 보여주는 구조, 설명용 전제, 실제 환경에서 관찰한 상태를 구분한다. 그림의 제목·범례·캡션에도 확인 범위를 표시한다. 고객 클러스터를 확인하지 않았다면 동작 중인 배포도로 단정하지 않는다.
- 에어갭 노트에서는 반입 경계·내부 registry·DNS·CA 등 해당 질문에 필요한 의존성을 표시한다. 근거가 없는 고객망 구성이나 외부 연결을 그려 넣지 않는다.

## 파일과 본문

GenOS 노트는 `Projects/GenonAI/`에 직접 작성한다. **SVG 정본도 해당 vault의 첨부 폴더에 둔다.** TIL 내보내기 사본이나 `til-sync` 대상처럼 취급하지 않는다.

1. 대상 vault의 `.obsidian/app.json`에서 `attachmentFolderPath`와 실제 폴더를 확인한다. 개인 vault의 기본 관례는 `Attachments/images`이며 `Attachements` 같은 별도 폴더를 만들지 않는다. 설정이 없거나 다르면 기존 첨부 관례와 사용자 지정 경로를 확인한다.
2. 플랫폼 그림은 `genos-<주제>-<그림>.svg`, 고객사 그림은 `genos-<고객사>-<주제>-<그림>.svg`처럼 출처와 용도를 구분한다. 같은 내용은 재사용하고, 이름이 겹치는 다른 그림은 새 이름을 쓴다. 기존 SVG를 갱신할 때는 참조하는 노트를 확인하고 노트·SVG를 백업한 뒤 승인된 범위에만 반영한다.
3. Markdown 이미지에 의미 있는 대체 텍스트를 넣고, **노트가 있는 폴더 기준으로 계산한 상대 경로**로 첨부 파일을 가리킨다. `![[Attachments/images/...svg]]` 임베드를 쓰면 바로 아래 캡션과 SVG의 `title`·`desc`로 의미 설명을 제공한다. 개인 PC 절대 경로는 본문에 쓰지 않는다.

예를 들어 노트가 `Projects/GenonAI/GenOS/02 아키텍처·K8s·Istio/`에 있고 첨부 폴더가 `Attachments/images`일 때:

```markdown
![클러스터 안의 두 Namespace와 클러스터 밖 registry의 배치](../../../../Attachments/images/genos-serving-namespace-layout.svg)

그림 1. 로컬 chart를 바탕으로 한 구성 설명이다. registry의 외부 배치는 예시 전제이며 고객 클러스터의 배포·연결 상태는 확인하지 않았다.
```

다른 깊이의 폴더에서는 위 `../` 개수를 그대로 복사하지 말고 실제 경로를 계산한다. 허브 등록은 기존대로 **Markdown 노트에** `vk register`를 실행한다. SVG 자체를 지식 노트로 등록하지 않는다.

## 표현과 검증

- SVG에 `viewBox`, `title`, `desc`를 둔다. 색상뿐 아니라 이름·선 종류·영역 라벨로 의미를 구분한다. 외부 폰트·이미지·네트워크 자원 없이 렌더되게 하고, 본문 표시 크기에서 한글·화살표·범례를 읽을 수 있게 한다.
- 여러 그림을 같은 규칙으로 생성한다면 생성 코드를 작업 범위에 맞춰 보관하고 실행 방법을 남긴다. 작은 SVG 하나는 직접 작성해도 된다. 검증용 PNG나 임시 파일은 최종 첨부 파일과 구분한다.
- XML 파싱과 링크 대상 존재를 확인한 뒤 **최종 SVG를 실제 렌더하고 이미지를 열어** 한글 깨짐, 글자 잘림·겹침, 화살표 끝, 여백, 배경·글자 대비를 확인한다. 파싱 성공이나 명령 exit 0은 시각 검증을 대신하지 않는다.
- 가능하면 Obsidian 본문에 삽입된 크기에서도 표시를 확인한다. 완료 보고에는 노트·SVG 경로와 실제로 수행한 검증을 적고, 렌더 또는 Obsidian 표시를 확인하지 못한 항목은 미확인으로 남긴다. 그림을 잘 렌더했다는 사실을 GenOS 실환경 동작 확인으로 확대하지 않는다.
