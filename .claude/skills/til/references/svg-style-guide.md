# 설명용 SVG 가이드

SVG를 선택했을 때 읽는다. 실행 위치·포함 관계·격리 경계처럼 공간 배치가 개념을 설명하는 그림에 사용한다. 비교표나 간단한 Mermaid만으로 충분하면 그 형식을 유지한다.

## 그림의 내용과 표현

- 그림마다 독자가 답을 얻을 질문 하나를 정한다. 제목과 캡션을 본문의 설명에 연결한다.
- 상자는 실행 위치·소유·포함 중 무엇을 뜻하는지 구분하고, 화살표는 호출·데이터 전달·제어 관계 등 의미를 표시한다. 논리 단계를 직접 통신 경로처럼 그리지 않는다.
- 생략한 구성, 특정 환경의 전제, 실제 관찰과 설명용 모델의 차이는 캡션에 밝힌다.
- Markdown 이미지에 의미 있는 대체 텍스트를 넣고 SVG에 `title`과 `desc`를 작성한다. 색상과 함께 이름·선 종류·영역 라벨로 구분한다.
- `viewBox`를 설정하고 본문 표시 크기에서 한글을 읽을 수 있게 만든다. 외부 폰트·네트워크 자원 없이 렌더되는 파일을 만들고, 배경·글자·선의 대비를 함께 확인한다.
- 여러 그림에 동일한 스타일·배치 규칙을 반복 적용할 때 생성 코드를 함께 둔다. 작은 SVG 하나는 직접 작성해도 된다. 생성 코드를 두었다면 실행 위치와 필요한 의존성을 짧게 기록한다.

## 저장과 본문 연결

일반 기술 글은 저장 대상의 자산 규칙을 따른다. 다음은 개인 TIL과 Obsidian에 적용하는 규칙이다.

| 대상 | 자산 위치와 링크 |
|---|---|
| TIL 원본 | `<category>/assets/<문서 또는 시리즈>/<그림>.svg`, 본문에서 상대 경로로 참조 |
| Obsidian 첨부 사본 | vault의 `Attachments/images/<충돌 없는 이름>.svg`, 해당 vault의 노트에서 이 사본을 참조 |

TIL의 SVG가 정본이며 Obsidian 사본을 유일한 원본으로 두지 않는다. 이미 정해진 시리즈 자산 경로는 유지한다. 파일명은 설명적인 이름을 쓰며, 한 폴더에 모으는 Obsidian 사본에는 `til-<category>-<문서 또는 시리즈>-<그림>.svg`처럼 출처를 구분할 이름을 권장한다.

```markdown
![앱·게스트 커널·호스트 커널의 포함 관계](./assets/runtime/kernel-boundaries.svg)

그림 1. 일반 Linux 컨테이너는 실행 호스트의 커널을 공유한다. VM 안에서 컨테이너를 실행하는 구성은 생략했다.
```

위 예시가 Wiki로 내보내졌다면 첨부 사본의 vault 내부 경로는 `Attachments/images/til-infra-runtime-kernel-boundaries.svg`다. Wiki 노트의 삽입 표기는 `![[Attachments/images/til-infra-runtime-kernel-boundaries.svg]]`처럼 대상 사본을 가리키게 하고, 본문의 의미 설명과 캡션은 유지한다. TIL 원본에는 이 vault 전용 경로를 쓰지 않는다.

## Obsidian 내보내기 확인

1. 대상 vault의 `.obsidian/app.json`에 있는 `attachmentFolderPath`와 실제 폴더를 확인한다. 이 가이드의 `Attachments/images`는 2026-10-24 개인 vault에서 확인한 기준 경로이며, 다른 시점·vault의 설정을 확인한 것으로 대신하지 않는다. `Attachements`처럼 비슷한 철자의 새 폴더를 만들지 않는다. 사용자 지정 경로와 현재 설정이 다르면 그 차이를 먼저 확인한다.
2. 내보내기가 작업 범위인 경우 자산을 복사하고, 평탄화된 Wiki의 이미지 링크를 첨부 사본 경로로 변환한다. 같은 대상 파일의 내용이 같으면 재사용한다. 관련 없는 기존 파일과 이름이 겹치면 출처가 드러나는 다른 이름을 쓴다.
3. TIL 파생 Wiki의 본문을 수동 치환하는 것으로 끝내지 않는다. 기존 동기화의 병합·백업·본문 해시(state) 규칙 안에서 변환해야 다음 동기화에서 사용자 수정으로 오인하거나 덮어쓰지 않는다. 공통 규칙은 `~/.dotfiles/vault/references/note-rules.md` 4절을 따른다.
4. 실제 자산 복사와 이미지 링크 변환을 지원하는지 동기화 구현을 확인한다. Markdown 노트가 생성되거나 커밋 훅이 있다는 사실만으로 이미지 동기화 완료를 판단하지 않는다. 미지원이면 TIL 자산 작성 완료와 Wiki 이미지 동기화 미완료를 구분해 보고하고, 동기화 기능 변경은 요청 범위에 포함될 때 구현·검증한다.

현재 구현을 확인할 위치는 `~/dev/TIL/.githooks/sync-to-obsidian.py`와 `~/.dotfiles/vault/vaultkit/tilsync.py`다. 2026-10-24 확인 시 이 경로는 Markdown 노트·문서 링크를 처리하며 SVG 자산 복사·이미지 링크 변환은 지원하지 않는다. 이후 지원 여부는 실제 코드로 재확인한다.

## 검증과 완료 보고

- SVG가 파싱되는지와 본문 상대 경로가 실제 파일을 가리키는지 확인한다.
- 브라우저나 SVG 렌더러로 **최종 파일을 실제 렌더**하고 이미지를 열어 한글, 글자 잘림·겹침, 화살표 끝, 여백, 대비를 확인한다. 파싱·명령 exit 0만으로 시각 검증 완료라고 하지 않는다.
- 본문에 삽입된 크기에서도 읽을 수 있는지 확인한다. 대상 뷰어에서 확인하지 못했으면 파일 렌더 확인과 구분해 보고한다.
- Wiki 내보내기를 수행했다면 첨부 사본의 내용·링크 해석·실제 표시를 확인하고 다음 동기화와 충돌하지 않는지 검증한다. 파일 존재 확인은 표시 확인을 대신하지 않는다.
- 커밋을 요청받으면 원고와 필요한 SVG·생성 코드를 함께 포함한다. 검증용 PNG·임시 렌더 파일은 독자에게 제공할 산출물로 정한 경우에만 포함한다.
